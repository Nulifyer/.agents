# Remote lifecycle

Before pushing, confirm the branch, upstream, commits to publish, and clean
separation from unrelated work.

After opening or updating a pull or merge request, report its URL, base and head
branches, title, and current check state that was actually observed.

When asked to monitor or babysit it, inspect checks and comments newer than the
last push. Verify automated findings against the source. Fix real issues within
scope and answer or dismiss false positives with a concrete reason. Stop at the
user's requested terminal condition.

Merge only when explicitly requested and required checks, approvals, and
repository policy allow it. Report the observed merge result, not an assumption
based on a button press.
